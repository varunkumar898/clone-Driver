1. PHASE IMPLEMENTATION OVERVIEW
--------------------------------------------------------------------------------
Phase 1: Build System & Workspace Initialization
  - Cargo workspace structure with strict compiler warnings (-D warnings).
  - Dependency tree configured: tokio, tauri, udev, nix, xxhash-rust, sha2.

Phase 2: Error Handling Architecture
  - Strongly-typed error hierarchies via thiserror: CloneError, StorageError,
    SafetyError, StateMachineError, ResumeError, ConfirmationError, PartitionError.

Phase 3: Hardware Discovery & Block Device Abstraction
  - Linux sysfs and udev enumeration with vendor, model, and serial metadata.
  - Partition table parsing supporting MBR and GPT headers.

Phase 4: High-Throughput Storage & I/O Engine
  - Direct block I/O with O_DIRECT and O_EXCL exclusive locking.
  - Aligned page buffer pool with recycling to prevent allocations.
  - Dynamic adaptive chunk sizing (4 MB to 64 MB based on rotational vs NVMe).

Phase 5: Checksum & Verification Pipeline
  - Streaming block-level xxHash64 hashing with optional full SHA-256 verification.
  - Multi-pass post-clone verification engine detecting bit-flips.

Phase 6: Multi-Layer Safety Architecture
  - Layer 1: Running OS Root/Boot disk protection (fail-closed NVMe & SATA checks).
  - Layer 2: Mounted partition detection and destination write blocking.
  - Layer 3: Capacity validation preventing undersized targets.
  - Layer 4: Anti-self-cloning protection (identical source and destination).
  - Layer 5: Three-stage state machine confirmation gate.
  - Layer 6: Exact-token manual entry verification ("CLONE TO THIS DISK").

Phase 7: Resume & Recovery Architecture
  - Checkpoint-based resumption for interrupted or crashed clones.
  - Atomic journal persistence via tempfile write + fsync + rename(2).
  - 24-hour checkpoint retention window enforcement (MAX_CHECKPOINT_AGE_SECS).
  - Hardware serial number verification preventing cross-device resume attacks.
  - Floor chunk alignment avoiding partial-chunk corruption.
  - Initial 4 MB block xxHash64 identity check.

Phase 8: Tauri Desktop UI & IPC Integration
  - Cross-platform desktop interface built on React, TypeScript, and Tauri 2.0.
  - Rust IPC backend in src/ui/state.rs and src/ui/handlers.rs.
  - Multi-step ConfirmationFlow component (Visual -> Text -> Final Check).
  - Real-time character validation for "CLONE TO THIS DISK".
  - Live progress display with MB/s transfer speeds, ETA countdown, and chunks.
  - Interrupted clone detection banner with one-click resumption.
